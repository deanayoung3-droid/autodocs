How it works

The agent does the reading and the first draft. You stay the editor.

  1. A pull request merges

    Docs Agent reads it and decides whether customers will notice: a renamed button, a new setting, a changed limit.

  2. Docs Agent drafts the change

    It finds the articles that describe that part of the product, rewrites the steps, and takes fresh screenshots.

  3. You review and publish

    Every change waits for you as a diff. Edit it, publish it, or send it back with a note.

Everything a help center needs

White-label from the first page: readers see your name, logo, colours and domain.

Help center
Sections and articles, search by keyword and meaning, AI answers with cited sources, feedback, translations, dark mode, and private docs.
Widget
One script tag adds search, AI answers and a contact form inside your own product.
Docs Agent
Drafts from merged pull requests, tasks you give it, and support questions. Runs scheduled audits and checks articles against your code.
Admin
An editor with live preview, a review queue with diffs, reporting on searches with no answer, and team accounts with roles.
Integrations
GitHub, Slack, Linear, 13 helpdesks for support signals, webhooks, a Chrome extension, and an MCP server for AI clients.
Import
Bring an existing help center over from its llms.txt or sitemap, with redirects from the old addresses.

Run it in 5 minutes

You need Node.js 24. The database is built in, so there's nothing else to install.

npm run setup writes your secrets, asks for an OpenAI key (you can add it later), and prints a setup password. Sign in at localhost:3000/login and name your help center.

  • On a server: Docker with automatic HTTPS
  • On Google Cloud: Cloud Run and Cloud SQL
  • After that: first steps
git clone https://github.com/deanayoung3-droid/autodocs.git
cd autodocs
npm install
npm run setup   # secrets, OpenAI key, setup password
npm run dev     # http://localhost:3000
